根据用户想要的交付物、已有材料和当前卡点选流程。优先采用用户点名的其他技能或指定的格式。已有数据、代码或论文时，从当前缺口接手。跨阶段任务给出顺序，每阶段选一个主技能，确有独立缺口时再加一个辅助。

## 判断用户要推荐还是要执行

- **推荐。** 用户只说目标、问该用哪套流程或明确要建议时，给出首选流程、选择理由、主技能和一条可复制的执行指令。确有需要时说明缺哪份输入。给出推荐后结束本轮。
- **执行。** 用户说“直接做”“继续训练”或明确要求制作、复跑、审查等具体动作时，选好路线，按需读取技能并完成任务。推荐后用户说“按这个做”时，沿用刚选的路线。
- 两种路线都合理时，根据现有材料给出有条件的首选。只有缺失的信息会实质改变路线时才追问。

## 按目标选流程

| 用户目标 | 推荐流程 | 主入口 |
| --- | --- | --- |
| 让 AI 用真题练完整流程或继续自主训练 | 从训练记录接手下一环，逐阶段验收 | [自主训练流程](references/autonomous-training.md) |
| 我想从零学真题、我们三人想合练 | 一步一练，手算后复跑，队友交叉核验 | `$mcm-team-drill` |
| 复跑已有案例、换输入跑现成脚本 | 核对输入与适用范围，运行本地入口，先读摘要 | `$mcm-fast` |
| 拿到陌生题或附件，想知道怎么做 | 先列逐问交付、数据和基准，再按题型选方法 | [审题建模](../mcm-model-training/SKILL.md)，必要时查[专项技能](references/specialist-skills.md) |
| 模型已定，想写可复跑代码或做仿真 | 按需求选实现或情景实验，给重跑命令及验收证据 | [代码与求解](../mcm-code-training/SKILL.md) 或 [仿真与灵敏度](../mcm-simulation-training/SKILL.md) |
| 有结果表，想做论文图或审图 | 按结果表出图，核对标签、单位和图中数值 | [可视化训练](../mcm-visualization-training/SKILL.md) |
| 有模型与结果，想要完整竞赛论文或 Overleaf 包 | 用已核验结果生成论文，按所用模板检查并交付 | [论文训练](../mcm-paper-training/SKILL.md) |
| 有稿件，想修编译、核对数字或审引用 | 按待查事项核对源稿和证据 | [论文训练](../mcm-paper-training/SKILL.md)，重点复核第三步 |
| 想复盘训练、定位实现错因或验证能否迁移 | 独立复算，做单错反例和新输入检查 | [训练复盘](../mcm-training-review/SKILL.md) |
| 想找公开文献、数据来源或建模方法依据 | 明确检索问题，优先核对原始来源 | 选用当前可用的文献或网页检索工具 |

## 执行与交接

- 只读取当前阶段需要的说明。先核对解释器、附件和可用求解器。专项技能尚未安装时，先按本包主流程推进，把可选依赖写进推荐。
- 个人陪练衔接用户做到的步骤，让用户先尝试。审排班时，从实际输出重算供需、出力和成本，并核对求解器状态。
- 正式比赛按该赛事当届规则确定 AI 使用范围与披露方式。交接时简述采用的技能、产物位置和已完成的验证。

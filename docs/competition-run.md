# 三人赛程、断点续跑和逐问验收

同一题以 `cases/<题名>/CASE.md` 交接。建模手、编程手和论文手各自负责一段工作，每个小问再指定一位复核人。原始附件保存在 `inputs/`，程序、结果与稿件按 `src/`、`outputs/`、`paper/` 放。 [三人全流程](end-to-end.md) · [CASE 模板](../templates/CASE.md)

## 定题与排时间

步骤、岗位和交付标准以[三人全流程](end-to-end.md)为准。开局比较候选题的附件完整性、首个可验算基线、后续小问风险和工具准备。由队伍确认选题。把带时区的官方截止、队内收尾时间及需要提前核对的特殊交付物填入 CASE。

往年题可以按陪练、自主训练或三人合练的目标推进。正式比赛先核对当届 AI 使用边界。2026 亚太赛的核心模型、算法设计与求解、结果分析均由队伍独立完成。 [正式比赛指令](codex-prompts.md#正式比赛) · [披露与学术诚信](ai-usage-disclosure.md)

## 换人或换聊天时接续

1. 运行 `python scripts/case_status.py cases/题目名`，看已登记的阶段、卡点和下一步。旧案例可以把模板的「进度与交接」和「决策记录」补到现有文件中，再从实际证据填状态。
2. 打开相应小问的交接行，确认上游结果的版本、字段、单位、覆盖范围和验收证据，再执行记录里的下一步。状态用「待开始」「进行中」「待复核」「通过」「需返工」「受阻」或「不适用」。结果已生成时先登记「待复核」。复核人对照实际证据后填写「通过」。
3. 需要人来定的事项留在决策记录里，例如原题有歧义、需要改关键假设或缩减目标。写下备选方案、影响和确认人。仍有独立的读题、取数、写作骨架或其他小问时，先推进这些工作。

## 哪些结果需要返工

- 定位最先失败的小问、场景或指标，写清实际值、限值、受影响版本和修复办法。
- 按交接表追踪直接及间接使用该结果的下游小问、图表、摘要和论文段落。将相关记录标为「需返工」，在新版本上重验，再更新证据；其他已验证结果可继续使用。
- 只要求部分数据时，核对该范围能否用。若下一问需要全程数据，只有局部通过时就标明缺口，让不依赖这段数据的工作先继续。 [宇树四问复盘](robotics-case.md#怎样闭合第四问) · [调度练习交接](../examples/dispatch/team-handoff.md)

## 时间快用完时怎么做

开局由队伍从官方截止倒排，为验算、编译、匿名审核、文件上传和重试留出缓冲。本队亚太赛仍按四日安排执行，11 月 29 日晚为队内提交目标。平时合练可以自己定收尾时间。到点优先复算主结论、收齐每问已验证的答案、编译和模拟上传。遇到硬约束或证据问题，修正后重验相关内容，或如实缩小结论范围。 [本队四日安排](apmcm-2026.md) · [英文交稿清单](apmcm-2026.md#英文赛项交稿检查)

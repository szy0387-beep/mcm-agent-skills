# 合成例题 · 两台机组的三小时调度

两台机组的出力和成本见 [units.csv](units.csv)，每小时需求见 [demand.csv](demand.csv)。每台机组可以关停，或按整数 MW 在出力上下限内发电。两台出力之和等于当时的需求。开机小时费用等于固定费用加上出力乘以单位费用。本例按小时独立计算。

从仓库根目录运行：

```sh
python .agents/skills/mcm-fast/scripts/dispatch.py examples/dispatch/units.csv examples/dispatch/demand.csv --output outputs/dispatch
```

| 小时 | 需求（MW） | A 出力（MW） | B 出力（MW） | 费用 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 35 | 35 | 0 | 200 |
| 2 | 95 | 80 | 15 | 500 |
| 3 | 55 | 55 | 0 | 280 |

正确的总费用为 **980**。在第 2 小时，两台都必须启用。A 的每 MW 成本更低，因此给 A 分配最大可行出力 80 MW，B 补 15 MW。结果文件包括逐时的 `schedule.csv` 和总费用 `summary.json`。

训练时可以把第二小时的需求换成 141 MW，程序应拒绝不可行输入。再把三小时需求都提高 10 MW，先手算新排班，再核对程序总费用 **1120**。做图时用 `schedule.csv`，让图和英文结果段引用同一份计算输出。

## 从英文题面做成论文

组员先各自读[英文题面](problem-en.md)，再打开下表核对。完整练习使用上面的两个原始 CSV，可以用手机核对第 2 小时，随后在电脑上复跑三个小问。

三人一起练时，可以使用[填好的交接示例](team-handoff.md)对照各岗位需要的文件、验算证据和入稿检查。

| 步骤 | 这一问留下什么 | 论文里放到哪里 |
| --- | --- | --- |
| 英文审题 | 第 1 问交每小时排班和总成本。第 2 问沿用第 1 问的规则，每小时增加 10 MW。第 3 问单独改第 2 小时的需求，判断是否可行。 | 引言列三问的交付物，数据段列两份输入。 |
| 数学建模 | `exactly` 表示供需相等。决策是两台机组每小时发多少，目标是最小化费用。关停时取 0，开机时用含端点的出力上下限。 | 模型段解释变量、成本函数和约束。 |
| 计算与验证 | 第 1、2 问各有一张排班表，成本为 980 和 1120。第 2 小时 95 MW 时，手算 80 + 15 MW 花费 500。第 3 问以 140 MW 的总上限检查 141 MW 的反例。 | 结果表和对照图使用同一次计算的输出，验算段解释手算与反例。 |
| 英文写作与编译 | 摘要报两种总成本，正文逐问回答，最后注明独立小时和整数 MW 的适用范围。 | 生成英文练习稿，检查文本、表格和图中的数字。 |

从仓库根目录运行以下命令。只需 Python 标准库，脚本会从原始附件生成排班表、核验记录和 LaTeX 源稿。

~~~sh
python examples/dispatch/run_paper.py --output outputs/dispatch-paper
~~~

检查 `outputs/dispatch-paper/paper/main.tex`。把 `paper/` 内的文件一起上传到 Overleaf，选择 `main.tex` 后编译。有本地 Tectonic 时，在 `paper/` 中运行 `tectonic main.tex`。

这道合成小题用来练怎样把题面、结果和论文对上。正式比赛用当届模板和提交说明。练完整真题时，按[首赛手册](../../docs/team-playbook.md)扩展到其他小问，并用[引用指南](../../docs/references-guide.md)核对外部来源。
